# GitHub wiki for 0.1.0 (main at 29bc397)

## Summary

Step 1 of the 2026-10-18 kickoff. The owner had saved the wiki's first page, so the wikiwright skill wrote twelve pages from the repository, the eval results and a verification program that downloads the repository zip at a pinned commit and runs every page command from it. Writing the wiki found three bugs in `hw.py`, fixed before the pages were pinned (PR #3 and #4, below). Wiki commit and check results: see "How it was published".

Pages: Home, Getting-Started, The-Skills, Commands, How-Dates-Are-Computed, How-Claims-Are-Checked, The-Research-Pack, Errors-and-Edge-Cases, Recipes, FAQ, Versions-and-Upgrading, Development, plus _Sidebar and _Footer.

historywright is neither an npm nor a NuGet package: a plugin of three agent skills plus a Python command-line tool, with no release yet (0.1.0 in plugin.json, no tag). The page set follows polywright's (the command-line-tool set with The-Skills, a behaviour page and a contract page in place of an API reference), with two behaviour pages (dates, claims). No registry, no golden captures.

## Updating the wiki later

1. `git -C <wiki dir> pull --ff-only`, then edit the pages.
2. Re-verify from the repository root, on Windows and in Linux (the pages show the Linux run for paths, L-132):
   `python ai-docs/notes/2026-10-18-wiki-verify.py <commit> > new.out.txt` and, in WSL,
   `python3 ai-docs/notes/2026-10-18-wiki-verify.py <commit> > new.linux.out.txt`. It downloads the repository
   zip at that commit into a temp folder and runs there with a fresh `HW_HOME`, no keys and no contact. It calls
   live keyless public APIs (Wikidata, Wikipedia, Pleiades, CHGIS, OpenAlex, Crossref, the Wayback Machine, DILA's
   download), about three minutes per run. Then
   `python <wikiwright>/scripts/wikiwright.py diffout ai-docs/notes/2026-10-18-wiki-verify.linux.out.txt new.linux.out.txt`:
   every changed section is a page to fix. Live answers drift when the sources are edited (Wikidata statements,
   OpenAlex counts, Wikipedia's reference total), so expect some. Save the new outputs over the old.
3. `wikiwright.py outputs <wiki dir> <the Linux output> --address ''`, `wikiwright.py snippets <wiki dir> ai-docs/notes/2026-10-18-wiki-verify.py`, `wikiwright.py check <wiki dir> --version <new>`, and the everwrite checker.
4. Commit, push, `wikiwright.py live m4bwav/historywright <wiki dir>`. Pages that name the version or the commit: _Footer, Home (last line), Commands (first sentence), How-Dates-Are-Computed, How-Claims-Are-Checked, Errors-and-Edge-Cases and Recipes (first sentence), The-Skills (cost section), Development (test count), FAQ (registry counts), Versions-and-Upgrading (table and the known doc errors). After the first release: a row per release in Versions-and-Upgrading, the install route via the release zip on Getting-Started, and the verifier's download switched to the release zip.

## Bugs found and fixed while writing (merged before the pages were pinned)

1. `HW_RECORD` wrote the raw URL (key values included) as the fixture pattern, and `check_skills.py` exempts `tests/fixtures/`, so a recording with a URL key would have been committed. Fixed in PR #3 (`record_pattern`).
2. `cal date "709 AUC"` and `"1300 AH"` (year first) were read as AD years with no warning; `"AH 1300"` covered the days of 1882, not of AH 1300; `"1 Muharram 1 AH"` came back as AD 1; Roman day counts failed with a misleading error. Fixed in PR #4.
3. `tests/check_skills.py` failed locally on the git-ignored eval results folder (runner paths). Fixed in PR #1.

## Facts verified while writing (not in the README)

- Argument errors print argparse's usage on stderr and exit 2; every other failure is JSON with exit 1.
- `place search` with no `--source` asks Pleiades and Wikidata, adds CHGIS only for names in Chinese characters and WHG only with a token. Results keep each gazetteer's order (Alesiai in Lakonia comes before Gallic Alesia).
- `doi` falls back to OpenAlex when Crossref has no record (10.20381/ruor-23791).
- `verify sources --offline` still requires each URL in this home's fetch log; `--any-url` lifts it.
- `src` sends the registry's own row limit (10 for the Wayback CDX) and cuts the list to `--limit` afterwards; the CDX index repeats captures and `src` does not merge them.
- `cal era 康熙` returns a second era under 世宗 (21 December 1722 to 4 February 1723).
- `read_as` for an AH year shows the Western year it starts in.
- The pace file keeps per-host gaps across runs and waits at most 30 seconds.

## Inaccuracies found in the shipped docs (wait for the first release)

1. README ("The skills" table), `.claude-plugin/plugin.json` (description) and `skills/historywright-sources/SKILL.md` ("Files"): "about 60 sources"; the registry holds 85 (`hw.py lint`).
2. README ("What a run looks like"): presents a four-line table as what `hw.py wd claims Q1048 --prop P569` prints; the command prints JSON, and the table summarises it.
3. `skills/historywright/references/cli.md`: "every command prints one JSON object"; argument errors print usage text and exit 2. It also leaves out `--limit`, `--lang`, `--max-age`, `--refetch`, `--name`, `--no-browser` and `keys --offline`.

## Gotchas

- The verifier's snippet runner maps a leading `python` to the running interpreter; Ubuntu has no `python` command.
- Mask only today's timestamps: a general timestamp mask also hits Wikidata's raw values.
- On Windows, a shell redirect of the first runs wrote the saved output with CRLF, which `check_skills.py` fails; the program now sets its stdout to LF.
- Running the Windows and Linux verifiers at once doubles the request rate per host (each has its own pace file); keep it to two.
